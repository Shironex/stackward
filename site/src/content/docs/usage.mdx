stackward runs on the server you want to audit. It reads, prints a report
and exits. Nothing on the server changes.

```
stackward audit [flags]     audit this host (sudo gives full coverage)
stackward explain [id]      explain a check, or list every check
stackward version           print the version
stackward probe <host>      check a host from outside (run from another machine)
stackward tui [flags]       browse the findings in the terminal
```

## Run an audit

```sh
# Partial coverage: checks that need root report unknown.
stackward audit

# Full coverage.
sudo stackward audit
```

Without root, every check that needs root reports `unknown`, and the report
says "run with sudo for full coverage". The read only promise holds either
way: root gives stackward more to read, not more to change.

### Flags

| Flag | What it does |
|---|---|
| `--json` | Print the report as JSON (same as `--format json`). |
| `--md` | Print the report as Markdown (same as `--format md`), for an issue or a handover note. |
| `--format text\|json\|md` | Output format. Text is the default. |
| `--out FILE` | Write the report to this file. It is the only file stackward ever writes. |
| `--fail-on fail\|warn\|never` | Which level makes the exit code 1. Default `fail`. |
| `--all` | Text and Markdown output: also list passing and skipped results (text: and every info result in full). |
| `--info` | Text output: list every info result in full instead of one line each. |
| `--group` | Text output: lay the results out by check group instead of by level. |
| `--plain` | Text output: no colors, Unicode or box lines, as when piped. `NO_COLOR` drops only the colors. |
| `--profile NAME` | Ingress profile: `auto`, `tunnel`, `public-web`, `tailnet-only` or `paas-panel`. Default `auto`. |
| `--dump-facts` | Print the collected facts as redacted JSON instead of a report, for bug reports. |
| `--facts FILE` | Evaluate the checks over a saved facts file instead of this host. |
| `--timeout DURATION` | Time limit for each collector. |
| `--show-hostname` | Print the hostname instead of its hash. |
| `--no-sandbox` | Do not apply the Landlock sandbox. For debugging only. |

`stackward audit -h` prints the same list from your build.

## Reading a report

The header comes first. Read it before the findings:

- **host** is a hash of the hostname unless you pass `--show-hostname`, so a
  pasted report does not name your server.
- **profile** is how traffic is meant to reach this server. It changes what
  counts as a problem (port 443 open to the world is fine on a public web
  server and a mistake behind a tunnel), never what is shown.
- **root** and **sandbox** say how much stackward could see and whether the
  Landlock sandbox was applied.
- **coverage** counts results that were checked, unknown and skipped. A
  report with many unknowns has not told you much yet.

On a terminal a summary box follows: the counts per level, the fails most
severe first and the commands to dig in. Then come the results by level:
fail, warn, unknown, then info. Each result leads with what was found, then
its check id, the severity from the catalog and the subject, the rule it was
measured against (the check title) and, for fail and warn, the fix. Info
results are one line each unless you pass `--info` or `--all`; `--group`
lays the results out by check group (SYS, SSH, NET, DKR and so on) instead.
Piped, written with `--out` or with `--plain`, the report is plain ASCII.

### Levels

| Level | Meaning |
|---|---|
| <Level level="fail" /> | Misconfigured in a way that matters. |
| <Level level="warn" /> | Worth a look. It may be deliberate; the message says why it was flagged. |
| <Level level="pass" /> | Inspected and fine. |
| <Level level="unknown" /> | Could not be inspected (no root, a missing tool, a collector error). **Never counted as a pass.** |
| <Level level="skip" /> | Does not apply to this host. |
| <Level level="info" /> | A fact worth knowing, with no judgement. |

Severity (`critical`, `high`, `moderate`, `low`, `info`) is a property of the
check, not of your server: it says how bad a failure of that check is. Fix
the highest severity `fail` results first.

<Aside type="caution" title="There is no score on purpose">
A single number hides a single critical finding behind many passes, and it
rewards checks that could not run. stackward gives counts and coverage
instead. See the [threat model](/stackward/project/threat-model/) for the
reasoning.
</Aside>

## Explain a check

```sh
stackward explain            # list every check
stackward explain SYS-002    # why it matters, verify, fix, what can break
```

The same text is on this site, one page per check, in the
[check reference](/stackward/checks/).

## JSON and Markdown output, and CI

```sh
sudo stackward audit --json --out report.json
sudo stackward audit --md --out report.md
```

Markdown is meant to be pasted into an issue or a handover note. Both
formats carry the same results as the text report.

The JSON report follows the `report.v1` schema in
[`schema/report.v1.json`](https://github.com/Shironex/stackward/blob/main/schema/report.v1.json).
Check ids are stable forever, so other tools can key on them.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | No result at or above `--fail-on` (default `fail`). |
| `1` | At least one result at or above `--fail-on`. |
| `2` | stackward itself failed (bad flags, an unreadable facts file). |

`unknown` never trips the threshold. Use `--fail-on warn` in CI to fail on
warnings too, or `--fail-on never` to always exit 0.

## Bug reports with facts

```sh
sudo stackward audit --dump-facts > facts.json
stackward audit --facts facts.json
```

`--dump-facts` prints what the collectors found, with secret shaped values
masked and the hostname hashed. `--facts` replays a saved file, so a report
can be reproduced on another machine. Read the file before you attach it to
an issue: redaction is a safety net, and you are the last reviewer.

## stackward probe

`audit` runs on the server and cannot see the provider firewall
([NET-009](/stackward/checks/net-009/) says so on every run). `probe` runs
from another machine, against a host you own, and shows what actually gets
through. Its results are the PRB checks, in the same report format.

```sh
stackward probe 203.0.113.10 \
  --profile tunnel --hostname app.example.com
```

What it sends, in full:

- plain TCP connects, over IPv4 and IPv6, to a short fixed port list (SSH,
  80 and 443, the Docker API, panel and dashboard ports, databases), plus at
  most 16 ports you add with `--ports`;
- a read of the first line an SSH server sends (at most 256 bytes);
- one `GET /` to the raw address on 80 and 443, without following redirects.
  The HTTPS request skips certificate verification, because an address has
  no certificate name to match, and the report says so;
- with `--hostname`, a request to `https://<hostname>/` with normal
  verification, following redirects on that same hostname only.

It ignores proxy settings from the environment, so the answers come from the
target itself. It refuses ranges, CIDR blocks, lists and URLs: one host only.
See [what probe does on the network](/stackward/project/threat-model/#what-probe-does-on-the-network)
in the threat model.

### Consent

Probing a host you do not own may be illegal. probe prints that and asks for
`y` on a terminal. When it is not on a terminal (a script, CI), it refuses to
run unless you pass `--i-own-this`.

### Flags

| Flag | What it does |
|---|---|
| `--hostname NAME` | Also check this app hostname over HTTPS (redirect loops, certificate problems). |
| `--ports LIST` | Extra TCP ports to try, comma separated, for example a moved SSH port. |
| `--profile NAME` | Ingress profile of the target: `auto`, `tunnel`, `public-web`, `tailnet-only` or `paas-panel`. Default `auto`. |
| `--i-own-this` | Confirm you own the host or may test it. Required when not on a terminal. |
| `--json`, `--format text\|json` | Output format. Text is the default. |
| `--all` | Text output: also list passing and skipped results. |
| `--plain` | Text output: no colors, Unicode or box lines, as when piped. |
| `--fail-on fail\|warn\|never` | Which level makes the exit code 1. Default `fail`. |
| `--out FILE` | Write the report to this file. |
| `--timeout DURATION` | Time limit for each TCP connect and banner read. Default 3s. |
| `--no-sandbox` | Do not apply the Landlock sandbox. For debugging only. |

probe has no host facts, so `--profile auto` judges open SSH and web ports as
if nothing should be public, and says so. Pass the profile that matches how
the server is meant to be reached. Probe the origin address: if a name points
at a CDN or tunnel edge, probe the origin and pass the name with
`--hostname`. An address family this machine cannot reach, often IPv6, is
reported as unreachable and its ports as `unknown`, never as closed. The
report names the target, so read it before you share it. Exit codes are the
same as for `audit`.

## stackward tui

```sh
sudo stackward tui
stackward tui --report report.json
stackward tui --facts facts.json
```

`tui` runs the same audit as `stackward audit`, with the same sandbox and the
same read only promise, and opens a findings browser: results by group, worst
first, with the full explanation, fix and verify steps of the selected check
beside them. `--report FILE` browses a saved `--json` report instead and
`--facts FILE` a saved facts file. `--profile`, `--timeout`, `--show-hostname`
and `--no-sandbox` work as they do for `audit`.

| Key | Does |
|---|---|
| Arrows, `j`, `k` | Move |
| `tab` | Switch between the list and the detail pane |
| `/` | Filter |
| `l` | Cycle the level |
| `a` | Show or hide passing and skipped results |
| `g` | Jump to the next group |
| `y` | Copy the fix to the clipboard |
| `?` | List every key |
| `q` | Quit |

Copying uses the terminal clipboard sequence (OSC 52) and only happens when
you press `y`. The browser writes no file. It needs a terminal of at least
60 by 16 and is laid out for 80 by 24. `NO_COLOR` turns colors off.
